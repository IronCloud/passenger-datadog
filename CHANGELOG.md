# Change log

## 2.0.0 (2026-08-14)

### New features

* Add `passenger-datadog install-service`, which generates a systemd unit for
  the host it runs on — resolving the Ruby interpreter, the executable, and
  `passenger-status` — and writes it to `/etc/systemd/system`. Supports
  `--dry-run`, `--force`, `--enable-now`, `--user`, `--group`, and
  `--passenger-status`
* Add `passenger-datadog uninstall-service`

### Changes

* Require Ruby >= 3.3 and Passenger >= 6.0
* Upgrade `dogstatsd-ruby` to 5.x; the client is configured for single-threaded
  operation so metrics are flushed per run without leaking sender threads
* Replace the `daemons`-based daemonization with a foreground process supervised
  by systemd, using a `Type=notify` unit generated by `install-service`
* The generated unit sets `PATH`, `GEM_HOME`, and `GEM_PATH`, so
  `passenger-status` resolves under systemd's minimal environment
* Warn instead of returning silently when `passenger-status` produces no output,
  which otherwise makes a misconfigured service look healthy
* Locate the XML declaration when stripping Passenger 4's non-XML header instead
  of dropping a fixed three lines. Any shorter non-XML output — such as the
  one-line error `passenger-status` prints when it cannot run — raised out of the
  collection loop, which `Restart=on-failure` turned into a restart loop
* Close the Datadog client from an `ensure`, so a send failure part way through a
  run cannot leak a socket per run
* Skip elements that contain only whitespace rather than sending them, which
  recorded a bogus zero
* Replace Travis CI with GitHub Actions
* Upgrade RuboCop to 1.x and refresh the configuration
* Move development dependencies from the gemspec into the Gemfile
* Add a Passenger 6.1 fixture captured from a live instance and a matching spec
